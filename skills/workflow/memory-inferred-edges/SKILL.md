## Skill: Memory Inferred Edges (memory-inferred-edges)

### Purpose

A memory graph built only from [[wiki links]] knows only what someone remembered to link. This skill finds the connections the notes' *meaning* supports — the decision in one note that silently governs the setup in another — and records them as INFERRED edges, kept clearly separate from the EXTRACTED links, so the graph can surface surprising connections without ever pretending a guess was written down.

### When to use

| Trigger | Example |
| --- | --- |
| The user asks what in the memory is connected, or to find hidden links between notes | "Unsa'y konektado ani nga mga note?" / "Find connections in my memory" |
| Several new notes were added and the graph should be re-examined | After a `reviewer memory init` + note-writing session |
| Planning work that touches past decisions, before reading the whole memory | "Before we plan, check what relates to the auth notes" |

Do NOT use when: the user wants the link written *into* a note — that is editing the note itself, and the resulting [[link]] is EXTRACTED by construction. This skill never touches the notes; it only proposes edges alongside them.

### Rules

1. **Write only `memory/inferred.json` — never edit `graph.json`, `INDEX.md`, or `REPORT.md`.** Those three are generated by `reviewer memory index`; hand edits are overwritten and bypass validation. Source: reviewer-harness `lib/memory.js` (generated-files design).
2. **Every edge names two notes that exist.** Use the exact note ids from `memory/INDEX.md` or `graph.json`. An id that does not resolve is rejected by validation and lands in REPORT.md under "Needs review — rejected inferred edges". Source: reviewer-harness `lib/memory.js` (`validateInferred`).
3. **Every edge carries a `confidence` in (0, 1] and a one-line `rationale` grounded in the notes' actual text** — name the shared decision, mechanism, or passage; never "these feel related". This mirrors Graphify's model: INFERRED edges are LLM-proposed and must carry a confidence score, distinct from EXTRACTED edges found verbatim in the source. Source: Graphify-Labs/graphify (Apache-2.0) — EXTRACTED / INFERRED edge vocabulary.
4. **Confidence bands:** 0.9–1.0 — one note explicitly names the other's subject (a decision, system, or file) without linking it; 0.7–0.89 — both notes describe the same mechanism or workflow in their own words; 0.5–0.69 — a real thematic link a human would probably accept; below 0.5 — do not write the edge. Source: general practice (Graphify scores inferred edges but publishes no banding; these bands are this skill's own calibration).
5. **Never duplicate an EXTRACTED link, and never mark anything EXTRACTED.** If the [[link]] already exists, the graph already knows; validation rejects the duplicate. INFERRED is a claim about meaning, EXTRACTED is a fact about text — blurring them destroys the graph's honesty. Source: reviewer-harness `lib/memory.js`; Graphify-Labs/graphify (edge tags).
6. **One edge per ordered pair.** If two proposals compete, keep the higher-confidence one with the sharper rationale. Source: reviewer-harness `lib/memory.js` (duplicate handling in `validateInferred`).
7. **After writing the file, run `reviewer memory index` and report back from `memory/REPORT.md`** — how many inferred edges were accepted, which were rejected and why, and which landed under "Surprising connections". Never report proposals as accepted before the index run proves it. Source: general practice (the harness's verification standard: report only what was run and observed).

### Validation gate

Before reporting the task done, check each line against the actual work:

- [ ] `memory/inferred.json` parses as a JSON array of `{from, to, confidence, rationale}` objects (optional `relation`).
- [ ] Every `from`/`to` is an existing note id; no self-links; no pair already linked by a [[wiki link]].
- [ ] Every rationale names concrete text from the notes — no vibes.
- [ ] `reviewer memory index` was run after the write, and the accepted/rejected counts reported to the user come from its output and REPORT.md, not from the proposal list.

### Examples

**Do:** two notes, `auth-flow` and `deploy-guide`, both describe the JWT session check but neither links the other:

```json
[
  { "from": "auth-flow", "to": "deploy-guide", "confidence": 0.8,
    "rationale": "Both describe the JWT session check; the deploy guide's cookie step assumes the flow auth-flow defines." }
]
```

**Do not:** editing `graph.json` directly to add the edge, inventing a note id that "should" exist, or setting confidence 1.0 on a thematic hunch — each either bypasses validation or lies about certainty.

### Sources

- Graphify-Labs/graphify (https://github.com/Graphify-Labs/graphify, Apache-2.0): the EXTRACTED vs INFERRED edge model — extracted edges are found in the source; inferred edges are proposed by the model and carry a confidence score. Rules 3, 5.
- reviewer-harness `lib/memory.js`: the `memory/inferred.json` storage format and its validation rules (existing notes only, confidence in (0, 1], rationale required, no extracted duplicates, strongest duplicate wins). Rules 1, 2, 5, 6.
- Rules 4 and 7 are labeled general practice where they appear — no source publishes them.
