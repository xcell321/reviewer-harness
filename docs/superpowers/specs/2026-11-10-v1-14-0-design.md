## Intent and why

v1.14.0 is the **working peak** of reviewer-harness (Edsiel's words): one roll-up release that ships
everything built and verified since v1.13.0, so the published version is the best working state of the
harness — all 22 skills verified working, the 8th runtime, every fix round, and the long-standing
Windows CRLF bug finally fixed. Nothing after v1.13.0 has been published anywhere (no npm, no GitHub
Release for v1.10.0–v1.13.0), so v1.14.0 rolls all of it up in one clean release.

## Goals

- Ship all 7 skills added since v1.13.0: `audit-team`, `ub-mode`, `design-taste-frontend`,
  `ui-ux-pro-max`, `vengeance-ui`, `brainstorming`, `writing-plans` (22 total, all verified WORKS).
- Ship the runtime additions since v1.13.0: Qoder as 8th runtime (v1.10.0), `system-design` (v1.12.0),
  `nodejs-quality` (v1.13.0).
- Ship all fix rounds: 6 thin skills rewritten, 2 defects fixed (vengeance-ui registries, ui-ux-pro-max
  touch targets), 4 content gaps fixed (no-hallucination, explain-bisaya, devops-basics,
  design-taste-frontend), explain-bisaya token analogy.
- **Keep `frontend-performance` (v1.11.0).** It was thin before (PARTIAL), then fixed (+4 rules) and
  re-tested WORKS. The old keep-vs-revert question is settled: keep, because it works now.
- Fix the CRLF parser bug so `sync` works on Windows without manual LF conversion.
- Publish once: npm `reviewer-harness@1.14.0` + one GitHub Release v1.14.0 with full highlights.

## Non-goals

- No new skills, no skill content changes, no runtime changes.
- No individual npm/GitHub releases for v1.10.0–v1.13.0 (roll-up only).
- No CI added (see Constraints — no test suite exists to run).
- No `bumpversion.md` created (see Constraints — the file never existed).

## Anti-goals (what would make this a failure even if it technically ships)

- A release whose npm package or Release notes list skills that don't work — every listed skill must
  have a verified WORKS verdict.
- A CRLF fix that changes sync output for LF files — LF behavior must be byte-identical before/after.
- A version bump that misses one of the two version files (package.json vs harness.config.json).

## Constraints (from recon, 2026-11-10, remote main HEAD `696051d`)

- **Version lives in two files:** `package.json:30` and `harness.config.json:46`, both `"1.13.0"`.
  `bin/cli.js:60` prints `v${config.version}` from the config. Both must bump together.
  (`lib/init.js:11` has `version: "1.0.0"` — that is the scaffold default for NEW projects, do not touch.)
- **CRLF root cause found — `lib/frontmatter.js`, `parseFrontmatter()`:**
  `text.startsWith("---\n")` is false for a CRLF file (`---\r\n`), so the whole frontmatter is
  silently dropped — name/description lost, body includes the raw frontmatter block. The end-marker
  search `indexOf("\n---\n")` fails on CRLF too. All skill/agent/command parsing flows through this
  one function (`lib/skills.js:134`, `lib/agents.js:27,39`, `lib/commands.js:27,38`), so the fix
  belongs here, once. No CRLF handling exists anywhere in `bin/` or `lib/` today.
- **README already lists all 22 skills** (Skills section) — no skills-list update needed. README has no
  numbered sections, so the old "§4.8 incomplete / §2.13 missing" flags are stale (no such sections
  exist). README version mentions are historical only (v1.0.0, v1.1.0 in "How it was built").
- **No CHANGELOG, no `docs/`** — release notes live in the GitHub Release, not in the repo.
- **No CI at all:** `.github/` contains only `skills/` (Copilot bundles); there is no `.github/workflows/`.
  `package.json` scripts is empty — no test script, no test suite. Adding CI is a separate decision
  (what would it run?); out of scope for this release.
- **`bumpversion.md` does not exist** in the repo (the "empty stub" flag was wrong — there is no file).
  Version bumps are a 2-line edit; no bump doc is created.
- **Sync already writes LF** (JS strings with `\n`) — only the parser needs the fix.
- **Push limits (standing):** GitHub App cannot write `.github/workflows/*`; `push-files` cannot delete
  files; verify every push against remote HEAD before and after. npm publish needs Edsiel's token
  (sent by him, used once, never stored). GitHub Releases have no connector tool — via browser, signed
  in as xcell321.

## Approaches considered

1. **Single roll-up v1.14.0 (picked).** Bump, CRLF fix, README v1.14.0 section, sync, push, one npm
   publish + one GitHub Release. Fits "working peak" and "ma update tanan": one clean release, one
   token use, one Release page listing everything since v1.13.0.
2. **Individual releases v1.10.0–v1.13.0 first, then v1.14.0.** Rejected: 4x the publish work, 4 token
   uses, and per-version history is not worth it for a roll-up release.
3. **v1.14.0 code-only, docs/flags later.** Rejected: "working na tanan" — the small docs work rides
   along; the only deferred items are CI and bumpversion.md (see Constraints — both are bigger
   decisions than they look).

## What gets built (the release checklist)

1. CRLF fix in `lib/frontmatter.js`: normalize `\r\n` → `\n` (and lone `\r` → `\n`) at the top of
   `parseFrontmatter`. Verification: a CRLF copy of a skill file parses identically to its LF twin
   (same name, same description, same body); `node bin/cli.js sync` output is byte-identical for LF
   input before and after the fix.
2. Version bump `1.13.0` → `1.14.0` in `package.json` and `harness.config.json`.
3. README: short v1.14.0 section — what's new since v1.13.0 (7 skills, Qoder, system-design,
   nodejs-quality, fix rounds, CRLF fix). No other README changes.
4. `node bin/cli.js sync` — regenerate runtime instruction files and bundles.
5. Push to `main` (push-files, Edsiel's approval card), verify remote HEAD + file contents.
6. npm publish `1.14.0` — needs Edsiel's npm token at publish time (he sends it, used once).
7. GitHub Release v1.14.0 via browser (signed in as xcell321) — highlights: what's new/different.
8. Verify: `npm view reviewer-harness version` shows 1.14.0; Release page live; `npx reviewer-harness`
   prints v1.14.0.
